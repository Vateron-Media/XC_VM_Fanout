# 02. Архитектура и поток данных

> Здесь — из каких частей состоит демон и как байты проходят путь от источника до
> зрителя. Детали каждого механизма вынесены в [04. Внутренние механизмы](04-internals.md).

## Общая схема

```
                     источник (mp2t / HLS / любой)
                                │
                    ┌───────────▼───────────┐
                    │   puller  ИЛИ  ingest  │   (мы тянем ИЛИ нам пушат)
                    └───────────┬───────────┘
                                │  188-байт-выровненные чанки MPEG-TS
                         Stream.Publish(chunk)
                                │
                       ┌────────▼─────────┐
                       │   Hub → tsjoin   │   единый буфер на поток
                       │  кольцо GOP + HLS│   (HLS — метаданный вид поверх кольца)
                       │  индекс сегментов│
                       └────────┬─────────┘
                          ┌─────┴─────┐
              GET /live/<id>        GET /hls/<id>/index.m3u8
              (video/mp2t)          GET /hls/<id>/<seq>.ts  (собирается из кольца)
                         │                 │
                     ┌───▼─────────────────▼───┐
                     │      nginx (X-Accel)     │  → зритель
                     └──────────────────────────┘
```

## Две HTTP-поверхности на разных unix-сокетах

Демон поднимает **два независимых HTTP-сервера**, каждый на своём unix-сокете (файл с
правами `0660`). Разделение — по назначению и доверию:

| Поверхность | Сокет (флаг) | Кто ходит | Что делает |
|-------------|--------------|-----------|------------|
| **Клиентская** | `-sock` | nginx (зрители) | Отдаёт видео: live TS и HLS. |
| **Управляющая** | `-ctl` | только PHP-панель | Регистрирует потоки, отдаёт статус, реконсиляция. |

Управляющая поверхность включается, только если задан флаг `-ctl`. Полный справочник
адресов — в [03. Endpoint’ы](03-endpoints.md).

Почему unix-сокеты, а не TCP-порты: они локальны для машины, имеют файловые права
(`0660`), их не видно снаружи, и обмен с nginx/PHP на той же машине быстрее.

## Внутренние части (пакеты `internal/…`)

| Пакет | Файл | Роль |
|-------|------|------|
| `server` | [server.go](../../internal/server/server.go) | Реестр `id → Stream`, обе HTTP-поверхности, жизненный цикл потока on-demand. |
| `hub` | [hub.go](../../internal/hub/hub.go) | Fan-out одного TS-потока множеству подписчиков; медленных отбрасывает. |
| `tsjoin` | [tsjoin.go](../../internal/tsjoin/tsjoin.go) | Единый буфер на поток: PAT/PMT + кольцо GOP’ов для «чистого входа» и prebuffer, **и** индекс HLS-сегментов, выведенный из этого кольца. |
| `hlscrypt` | [hlscrypt.go](../../internal/hlscrypt/hlscrypt.go) | AES-128-CBC шифрование HLS-сегментов (совместимо с панелью), применяется на лету в момент сборки сегмента. |
| `puller` | [puller.go](../../internal/puller/puller.go) | Захват источника (прямой mp2t или ремукс ffmpeg), reconnect с backoff. |
| `ingest` | [ingest.go](../../internal/ingest/ingest.go) | Копирование TS-потока в publish-колбэк 188-байт-выровненными чанками. |
| `config` | [config.go](../../internal/config/config.go) | Мост настройки панель↔демон: самоисцеляющийся JSON-файл, опрашивается и применяется на лету. |
| `defaults` | [defaults.go](../../internal/defaults/defaults.go) | Встроенные константы операционной настройки (сиды конфиг-файла и прочие инварианты). |
| `cmd/xc_fanout` | [main.go](../../cmd/xc_fanout/main.go) | Точка входа: флаги, загрузка/опрос конфига, поднятие сокетов, graceful shutdown. |

## Ключевые сущности

### Manager

Реестр всех потоков, ключ — `id` (строка). Хранит настройки по умолчанию (размеры,
таймауты), создаёт `Stream` по требованию (`GetOrCreate`), маршрутизирует HTTP-запросы
обеих поверхностей и запускает **рипер** (фоновую уборку простаивающих потоков).

### Stream

Один живой поток. Объединяет:

- **`Hub`** — fan-out плюс единый буфер `tsjoin`, обслуживающий **и** live TS, **и** HLS
  (HLS выведен из кольца — отдельного сегментатора нет);
- **состояние жизненного цикла** — тянем/не тянем, число зрителей (`refs`), метки
  времени последних данных и последнего доступа, ключ шифрования, гейт простаивающего
  буфера.

Все данные входят в `Stream` через единственную точку — метод `Publish`.

## Поток данных: от источника к зрителю

1. **Захват.** Источник попадает в демон одним из двух путей: **`puller`** тянет его сам —
   это **только proxy-стримы** (`direct_proxy=1`, у них нет панельного ffmpeg); **`ingest`**
   принимает push от продюсера — это **обычные (non-proxy) стримы**, где панельный ffmpeg
   отдаёт свой готовый вывод вторым выходом `-f tee`. То есть прямой пул источника — только
   для proxy; обычные стримы демон получает как вывод ffmpeg. Подробнее —
   [04, разд. «Захват источника»](04-internals.md#захват-источника--puller).
2. **Выравнивание.** Байты режутся на чанки, кратные 188 (длина TS-пакета), чтобы
   парсеры ниже всегда видели целые пакеты (`ingest.Copy`).
3. **Публикация.** `Stream.Publish(chunk)` подаёт чанк в `Hub`, который сворачивает его в
   единое кольцо `tsjoin`, и обновляет метку живости `lastData` (для off-air-детекции).
   Буфер один — и TS, и HLS обслуживаются из него.
4. **Раздача TS.** Каждый зритель `GET /live/<id>` получает от `Hub` сначала
   «снимок для чистого входа» (PAT/PMT + текущий GOP, опционально prebuffer), затем
   живой хвост. Медленный зритель отбрасывается, чтобы не тормозить остальных.
5. **Раздача HLS.** HLS — это **вид поверх кольца**: индекс сегментов (только метаданные)
   задаёт плейлист, а каждый запрос `<seq>.ts` собирается из GOP’ов кольца на лету
   (шифруется, если у потока есть ключ). Плеер опрашивает `index.m3u8` и качает `<seq>.ts`.
6. **Наружу.** Живой TS и HLS-**сегменты** отдаёт nginx через `X-Accel`, проксируя на
   клиентский сокет. HLS-**плейлист** (`index.m3u8`) — исключение: его забирает и
   переписывает под авторизованные URL сам PHP (см.
   [07. Интеграция](07-integration.md#nginx--переносит-байты-наружу)).

## Принципы, заложенные в дизайн

- **Один источник — много зрителей.** Источник тянется один раз (`Hub` копирует
  каждый чанк подписчикам).
- **PHP вне байтового тракта.** Видео не проходит через PHP — только команды управления.
- **Ничего на диск.** И TS, и HLS живут в оперативной памяти.
- **Один буфер, а не два.** Единое TS-кольцо на поток обслуживает live-TS *и* HLS (HLS —
  метаданный вид поверх него); поток, который никто не смотрит, сжимает это кольцо. См.
  [ADR 0001](../adr/0001-single-ts-cache-hls-on-demand.md).
- **On-demand.** Источник тянется, только пока есть зрители; иначе останавливается
  (см. [05. Жизненный цикл](05-lifecycle.md)).
- **Медленный не тормозит быстрых.** Зритель, не успевающий вычитывать данные,
  отбрасывается, а не блокирует поток.
- **Статический бинарник.** Никаких зависимостей — копируешь и запускаешь.
