# 08. Сборка, тесты и релиз

> Как собрать демон, прогнать тесты и выпустить новую версию. Как готовый бинарник
> попадает на серверы панели — см. [07. Интеграция](07-integration.md#установка-и-обновление-бинарника).

## Требования

- **Go ≥ 1.21** (модуль `github.com/Vateron-Media/XC_VM_Fanout`, см. `go.mod`).
- Внешних C-зависимостей нет: сборка идёт с `CGO_ENABLED=0` → **статический бинарник**,
  работающий на любом Linux-дистрибутиве.
- Для работы (не сборки) на не-mp2t источниках нужен `ffmpeg` на целевой машине.

## Разработка

```bash
go test ./...            # юнит-тесты всех пакетов
go vet ./...             # статический анализ
go run ./cmd/xc_fanout -h   # список флагов
```

У каждого внутреннего пакета есть тесты рядом с кодом (`*_test.go`): `hub`, `tsjoin`,
`hlsseg`, `hlscrypt`, `ingest`, `puller`, `server` (включая отдельный тест на сброс
залипшего зрителя `serve_live_stall_test.go`).

## Выпуск версии

```bash
./release.sh 0.7.0                       # go test + сборка dist/xc_fanout-linux-* + SHA256SUMS
git commit -am "release 0.7.0"
git tag 0.7.0 && git push --tags          # тег БЕЗ префикса "v" — соглашение проекта
```

Что делает `release.sh`:

1. прогоняет `go test ./...`;
2. собирает статические бинарники под архитектуры в `dist/xc_fanout-linux-*`;
3. считает контрольные суммы `dist/SHA256SUMS`.

Версия штампуется в бинарник при сборке через `-ldflags "-X main.version=…"`, поэтому
`xc_fanout -version` печатает именно версию релиза (панель по ней решает, нужно ли
обновляться).

## Что происходит после push тега

Push тега вида `[0-9]*` (например `0.7.0`) триггерит workflow
[`.github/workflows/release.yml`](../../.github/workflows/release.yml):

1. checkout, установка Go 1.21;
2. `./release.sh "${GITHUB_REF_NAME}"` — пересборка бинарников и контрольных сумм;
3. публикация ассетов (`dist/xc_fanout-linux-*` и `dist/SHA256SUMS`) на **GitHub Release**
   через `softprops/action-gh-release`.

Альтернатива вручную:

```bash
gh release create 0.7.0 dist/*
```

## Соглашения проекта

- **Теги версий — без префикса `v`** (`0.7.0`, не `v0.7.0`). Workflow слушает шаблон
  `[0-9]*`, и `release.sh` печатает сообщения под этот же формат.
- **Бинарники не коммитятся** в дерево — `dist/` в `.gitignore`; распространение только
  через ассеты Release.
- **Источник правды — версия в бинарнике.** Панель читает её через `-version` и сверяет
  с последним тегом релиза.
