# 06. Параметры и конфигурация

> Что демон потребляет на входе: флаги командной строки, их значения по умолчанию и на
> что каждый влияет. Точка входа — [`cmd/xc_fanout/main.go`](../cmd/xc_fanout/main.go).

У демона **нет конфиг-файла** — всё задаётся флагами командной строки при запуске.
Динамика (какие потоки обслуживать) приходит уже в рантайме через
[управляющий API](03-endpoints.md#управляющая-поверхность-только-для-php).

## Полный список флагов

| Флаг | По умолчанию | Назначение |
|------|--------------|------------|
| `-sock` | `/home/xc_vm/bin/xc_fanout/sockets/http.sock` | Клиентский unix-сокет (сюда ходит nginx/зрители). |
| `-ctl` | `""` (выкл.) | Управляющий unix-сокет (только PHP). Пустой = управляющего API нет. |
| `-ingestdir` | `<каталог -sock>/ingest` | Каталог per-stream push-сокетов (для ingest-режима). |
| `-grace` | `10` | Секунд держать источник живым после ухода последнего зрителя (окно рипера). |
| `-write-timeout` | `15` | Секунд, сколько одна запись зрителю может залипнуть до сброса соединения. |
| `-prebuffer-max` | `20` | Потолок (сек) удерживаемой TS-истории на поток; клиентский `?prebuffer=` зажимается этим значением. |
| `-chunk` | `12032` | Размер чтения ingest в байтах (выравнивается вниз до кратного 188). |
| `-maxgop` | `10528000` | Максимальный размер join-снимка (байт) — защита памяти для потоков без ключкадров. |
| `-hlstarget` | `6` | Целевая длительность HLS-сегмента (секунды). |
| `-hlswindow` | `6` | Сколько HLS-сегментов держать в скользящем окне. |
| `-ffmpeg` | `ffmpeg` | Путь к бинарнику ffmpeg (для ремукса не-mp2t источников). |
| `-version` | — | Напечатать версию и выйти. |

### Флаги режима «launch / test»

Для изолированного тестирования — подать один поток прямо при старте, без control API:

| Флаг | Назначение |
|------|------------|
| `-id` | Идентификатор потока, который подать при старте (пусто = только обслуживать). |
| `-source` | Источник(и) для `-id`, через запятую (pull-режим). |
| `-in` | Входной файл для `-id`, либо `-` для stdin. |
| `-ua` | User-Agent источника. |
| `-proxy` | HTTP-прокси источника `host:port`. |
| `-cookie` | Значение заголовка `Cookie` для источника. |

`-source` и `-in` взаимоисключающие: первый — тянуть по URL, второй — читать из файла/stdin.

## На что влияют ключевые параметры

### Тайминги жизненного цикла

- **`-grace`** — насколько «инерционен» источник. Больше значение = источник дольше живёт
  после ухода зрителей (быстрее подхват при возврате, но дольше висит впустую). Рипер
  тикает каждые `grace/2`. См. [05. Жизненный цикл](05-lifecycle.md).
- **`-write-timeout`** — порог сброса «залипшего» зрителя. Меньше = быстрее чистим мёртвые
  соединения, но выше риск задеть медленного, но живого. 15 с — с запасом, т. к. здоровый
  realtime-зритель копит ≤1 с отставания в секунду. См.
  [04, «Защита от залипших зрителей»](04-internals.md#защита-от-залипших-зрителей).

### Память и буферизация

- **`-prebuffer-max`** — потолок истории TS, которую поток держит в памяти на случай
  клиентского prebuffer. Прямо влияет на потребление RAM на поток. Клиентский
  `?prebuffer=<сек>` зажимается этим значением.
- **`-maxgop`** — предел размера одного GOP-снимка. Защита от роста памяти на потоках,
  где ключкадры редки или отсутствуют.
- **`-chunk`** — размер порций чтения источника. Выравнивается вниз до кратного 188
  (длина TS-пакета).

### HLS

- **`-hlstarget`** — целевая длина сегмента (реальная длина плавает, т. к. режем по
  ключкадрам). Влияет на задержку HLS и частоту сегментов.
- **`-hlswindow`** — сколько последних сегментов доступно. Больше окно = длиннее «хвост»
  для перемотки/догоняющих плееров, но больше RAM.

> Сегментатор подстраховывается от некорректных значений: `-hlstarget ≤ 0` трактуется как
> `6`, `-hlswindow < 1` — как `3`. При запуске из `main.go` значения всегда валидны, так
> что этот фолбэк срабатывает только при программном создании `Segmenter` с иными числами.

### Пути и доступ

- **`-sock` / `-ctl` / `-ingestdir`** — размещение unix-сокетов. Демон при старте создаёт
  каталоги, удаляет старые файлы сокетов и слушает с правами `0660`. Если `-ctl` пуст —
  управляющий API не поднимается вовсе (демон работает только на раздачу).

## Что происходит при старте

1. Разбор флагов (`-version` → печать версии и выход).
2. Создание `Manager` с размерами/таймаутами из флагов.
3. Создание каталога ingest-сокетов, запуск рипера.
4. Поднятие клиентского HTTP-сервера на `-sock`; если задан `-ctl` — и управляющего.
5. Если задан `-id` — разовая подача тестового потока.
6. Ожидание сигнала; по `SIGINT`/`SIGTERM` — graceful shutdown (2 с) и удаление сокетов.

## Пример запуска

```bash
# Боевой режим: обе поверхности, источники приходят через control API
xc_fanout \
  -sock /home/xc_vm/bin/xc_fanout/sockets/http.sock \
  -ctl  /home/xc_vm/bin/xc_fanout/sockets/control.sock \
  -grace 10 -write-timeout 15 -prebuffer-max 20 \
  -hlstarget 6 -hlswindow 6

# Тест одного потока из файла, без control API
xc_fanout -id test -in ./sample.ts

# Тест одного потока с внешнего URL
xc_fanout -id test -source https://example/live.m3u8 -ua "Mozilla/5.0"
```
